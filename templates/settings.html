spread = price(Leg B) − β × price(Leg A). Use 1 for the same underlying (e.g. XAUUSD vs GC1225). For a cross pair (e.g. gold vs silver) set β so the legs are comparable — Leg A is scaled by β to stay dollar-hedged. The suggestion above is mid(Leg B) ÷ mid(Leg A) from live broker prices when the legs are DIFFERENT instruments — that equalises them in money. For the same underlying (spot vs its own future) the suggestion is 1: the spread there IS the basis, and scaling it away by the price ratio would delete the signal. β is not a contract-size or lot ratio — contract sizes are handled when sizing the hedge.

Collect for at least this long before trading — 7200 = 120 minutes. A quote count alone is not the same thing: 300 quotes arrive in about 3 minutes on a live gold feed. Capped at the Lookback Window, since older data is discarded anyway. 0 = no time gate.

The spread's standard deviation must be at least this big for z to be trusted. z is the spread divided by sigma, so a quiet session with a tiny sigma manufactures a huge z out of nothing — that is how a live run once printed z = 53,026. Position Sizing
A lot is a different amount of money on every instrument, so sizing by lots means the same setting is $21m of gold and $80k of oil. Sizing by notional fixes the money and derives the lots from the live price — the only way two different instruments end up balanced against each other.
Money on ONE leg — NOTIONAL_PER_LEG_USD. Lots = notional ÷ (contract size × price), rounded down to a tradable step. The hedge leg is then derived from this leg and both contract sizes, so the pair balances even when the two contracts differ. Margin actually locked is this ÷ the leg's leverage.
Unit-neutral holds the same quantity on both legs weighted by β, so the pair's P&L is exactly the spread move the z-score is measured on. The legs' dollar values then differ by the basis — which is the thing being traded, not an imbalance. Correct for spot-vs-futures.
Dollar-neutral puts the same money on each leg, so the pair trades the return spread. Correct for two related instruments with no arbitrage tying them (WTI vs Brent). The two agree only when β equals the live price ratio; the dashboard warns when they diverge.
LOTS, not dollars — this is CLIP_LOTS. Notional = lots × contract size × price, so 50 lots of gold at 100 oz/lot is over $21m per leg. The futures leg's minimum is usually larger than spot's; keep this at or above it. Capital required (live): —
Hard cap — MAX_LOT_SIZE. The risk manager refuses any entry whose Leg A lots exceed it. Always in LOTS, whichever way you size: when sizing by notional the derived lots must still clear this, so a cap below them blocks every trade.
A clip is worked in child orders of this size — SLICE_LOTS. 0 = send the whole clip at once. A child order below EITHER leg's minimum volume is rejected before anything is placed.
Mark-to-market headroom on top of required margin (fees, slippage, drift). The pre-trade balance guard requires available ≥ margin × (1 + this%). Default 10%; raise to 30% for more safety on volatile pairs.

Broker Charges (round-trip cost)
What one complete trade costs — four executions: open both legs, close both legs. This is the number the Edge Filter measures the expected capture against, the Profit Cost Floor stands on, and the Expected Value charges to the losing side. Setting it too high silently blocks every good trade; too low and the engine trades through its own costs.
Round trip = the bid-ask you cross on each leg (measured live from the feed — nothing to type) + commission per lot (below).

MT5 Brokers & Legs
How MT5 connections work

One MT5 terminal serves one account. All three topologies are supported:

  • Leg A → Broker A / Account 1 and Leg B → Broker B / Account 2 — two terminals, one leg runner each
  • Both legs → Broker A, two different accounts — two terminals
  • Both legs → one account — a single terminal, no leg runners

Passwords are written to the local .env file — never into config or git. Account changes take effect when the launcher is restarted.
